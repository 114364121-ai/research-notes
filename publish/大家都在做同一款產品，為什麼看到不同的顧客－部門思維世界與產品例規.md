# 大家都在做同一款產品，為什麼看到不同的顧客？

單面鏡的一邊，坐著一群穿著保守商務服裝的產品開發者。另一邊，有個人穿綠色 T 恤和牛仔靴，腰帶上扣著一塊大銀扣。他是當地微電腦俱樂部的會長，也是這群人得學著理解的新客戶。

這是 Dougherty 在研究一家電腦與通訊設備商時記下的場景。對習慣把設備賣給企業的 SALECO 來說，知道市場上多了一群使用者，和知道這群人拿到電腦會做什麼，是兩回事。只要兩者還混在一起，一份看似完整的市場分析，就足以讓人放心地把產品做下去。

## 每個部門都有一套看得很清楚的地方

Dougherty 把部門長期養成的專業眼光稱為「思維世界」（thought world）。第一線人員聽到顧客抱怨，想到的是哪一種用法卡住了。工程人員聽到同樣的抱怨，可能先問這是不是普遍到值得修改設計。製造人員接著會問，改動對生產有什麼影響。每個問題都合理，合起來卻未必有人回答：這款產品究竟該為誰做？

這些差異平時有用。產品成熟、客戶熟悉的時候，各部門依照例規完成自己的工作，無須每次從頭商量。然而一旦產品面對陌生的使用者，例規也會替團隊省掉一些該重新問的問題。當市場已經被寫成銷量和價格的試算，使用情境反而容易變成一個大家以為別人已經確認過的細節。

## 同一家公司，兩次不同的開發

在第一代 System I，團隊透過焦點團體接觸新使用者，也讓不同職能共同參與設計。他們外購現成零件來壓低價格，並採開放架構，讓外部開發者為機器撰寫軟體。對 SALECO 過去的設備來說，耐用和由自家掌控是值得維持的標準。換到 System I 的市場，買得起、找得到想用的軟體，同樣是產品好不好用的一部分。

到了 System II，部分人員和技術延續下來，團隊卻回到熟悉的矩陣分工。市場做過分析，產品也有獨特功能，但那些功能沒有先讓使用者試用。最後做出來的機器耐用，售價也高。銷量未能支應製造成本，產品被取消。兩個案例無法單獨證明某種分工造成成敗，卻讓人看見，延續上一代的技術和人員，仍可能丟掉上一代用來認識顧客的方法。

## 多一份市場報告，會改變哪一個決定？

把這篇研究帶回開發會議，我想先問的是：團隊上一次因為看見顧客怎麼使用產品，而改掉一個原本很確定的決定，是什麼時候？可以讓業務、工程與製造一起看同一次試用，然後各自說出，剛才哪個細節值得改規格、改價格，或再去問一次使用者。彼此的判斷可能仍有差異，但至少可以指出分歧從哪裡來。

單面鏡另一邊的人沒有義務長得像公司原先想像的客戶。真正值得留意的時刻，是團隊已經看見了他，卻還找不到一個地方，可以把這份觀察寫進下一版設計。
